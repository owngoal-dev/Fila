# Fila 手动测试素材

本目录提供原创音频和可重复生成的普通文件，用于界面与文件操作测试。它们不是测试通过的证据，也不包含真实用户的音乐数据库、设备身份、登录信息或安装引导路径。未引入生产依赖。

## 生成普通文件

在仓库根目录执行，使用已有临时目录下的一个**尚不存在**的子目录：

```sh
python3 Tests/Fixtures/generate.py --output /tmp/fila-fixtures-example
```

脚本仅使用 Python 3 标准库，默认生成 64 MiB 的 `ProgressFixture.bin`。`--progress-mib 0` 可跳过大文件，范围为 0–1024；`--seed` 默认 `20260906`，范围为无符号 64 位整数。相同参数产生相同的文件内容；进度数据由固定种子的 SHAKE-256 流生成，归档成员和 gzip 头的时间均固定为 0。在相同 gzip/zlib 实现下，压缩归档也逐字节一致。

输出目录必须不存在，父目录必须已存在；现有目录、文件和符号链接都会被拒绝，脚本没有覆盖选项。每个输出文件也使用独占创建。若生成中途失败，脚本返回非零状态并指出留下的目录，不会递归删除未知内容。请确认后只清理本次生成的文件及空目录。

`Manifest.json` 记录参数、文件大小及 SHA-256；`SHA256SUMS.txt` 可用于复制前后核验，例如在输出目录运行 `shasum -a 256 -c SHA256SUMS.txt`。大文件不应加入版本控制；本目录的忽略规则覆盖 `ProgressFixture.bin` 和 `generated/`。

仓库中的 `Filesystem-Validation.json` 保存默认参数在本机生成并验证的参考哈希。相同参数应产生相同字节；归档条目与内容、现有目录/符号链接及越界参数的拒绝行为以生成器为准。三段 M4A 的标签、时长与哈希见 `Music/`。

| 素材 | 验证目标 | 完成后的清理 |
| --- | --- | --- |
| `control.tar.gz` | 包含 `./` 根项、`./control`、`./note.txt`、`./images/`。预览应隐藏无意义根项，其余项目使用统一文件/目录图标；默认解压目录名应为 `control`，核对内容和空目录 | 删除这次生成的归档及独占解压目录 |
| `TrashFixture.txt` | 移到废纸篓后原路径消失；Put Back 恢复原路径和相同字节；永久删除只针对本样本 | 核对恢复后删除样本；若测试停在废纸篓中，按该样本身份单独清理 |
| `CrossVolumeFixture.txt` | 跨卷移动/移到废纸篓的成功与失败反馈、一次性提示、失败后源文件保留 | 核对成功/失败结果，再分别清理测试源和测试目标中的样本 |
| `ProgressFixture.bin` | 压缩、解压和复制的进度卡、后台运行、取消、正向弹簧推进及归零；64 MiB 不易压缩数据通常比小文件更便于观察 | 确认任务已经终止，再移除本次源、输出及残留临时文件；不要用任意进程终止来模拟取消 |
| `Music/*.m4a` | 音乐列表、元数据读取、原生保存及刷新结果；见音乐子目录说明 | 通过系统音乐管理流程移除本次导入的三首测试歌曲，不删除或替换系统数据库 |

`control.tar.gz` 是预览用 tar 归档，只有普通文件和目录；它不是可安装的 deb，也没有维护脚本。此素材包没有可安装 IPA。

## 设备使用范围

只放到应用拥有的、专门为这一轮测试创建的独占临时目录。通过运行时后端定位临时目录，不使用复制来的引导前缀或历史设备目录。执行前确认目标身份和目录归属；不要把这些素材放进系统配置目录或真实用户文件中。

跨卷测试需要两个实际不同的挂载卷。路径字符串不同、符号链接不同，或引导目录与普通目录不同，都不能证明跨卷；先解析路径并比较真实挂载信息，再选择两边可写且仅属于本轮测试的临时位置。只有一个可用卷时应记录未覆盖，不能把普通目录移动记录成跨卷通过。

只清理本轮创建的内容，先等待对应任务完成或确认取消；不要清空用户的整个废纸篓。记录源/目标大小和哈希、界面结果、取消是否确认及清理结果，不把已接受的请求当作完成。

## 音乐素材

`Music/` 收录三段原创合成音频及其标签验证报告。它们必须先经系统音乐支持的导入/同步流程成为资料库条目，直接复制到设备文件夹不会做到这一点。不得覆盖 `MediaLibrary.sqlitedb` 或其 WAL/SHM 文件。
